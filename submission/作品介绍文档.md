## 一、封面

**作品名称：** VelaGesture

**一句话描述：** 基于 openvela 的多模态智能手势交互终端，将视觉手势、语音和业务上下文转化为结构化交互事件，通过 ai_agent 驱动 Skill 完成工业控制场景下的任务执行。

**关键特性：**

## 二、项目概览

VelaGesture 是一个面向工业控制和数字孪生场景的多模态智能手势交互终端。它运行在 ESP32-P4 Function-EV-Board 上，基于 openvela（NuttX-based RTOS）操作系统，通过摄像头识别手势、麦克风采集语音，将用户的物理交互转化为结构化事件，并由 AI Agent 驱动 Skill 执行任务。

**重要说明：本项目不是从零开发。** 它是在已有的「多模态智能手势交互终端」原型基础上，向 openvela / ESP32-P4 嵌入式平台的迁移与系统升级。原有原型已具备手势识别、稳定门控、WebSocket 通信和业务系统联动能力，本次参赛将这些能力迁移到嵌入式硬件平台，并新增了 ai_agent 和 Skill 执行能力。

## 四、项目痛点与应用场景

### 4.1 痛点

1. **工业控制中的交互瓶颈** — 在水利监控、数字孪生等场景中，操作员需要在大屏前快速响应告警，但键盘鼠标交互效率低。
2. **多模态需求** — 单一交互方式（仅触屏或仅语音）无法满足复杂业务场景。
3. **端侧智能** — 纯云端方案延迟高、依赖网络，需要端侧感知能力。

### 4.2 应用场景

1. **水利监控** — 古贤水利枢纽的闸门水位监控，操作员通过手势确认告警、查询状态。
2. **工业控制** — 生产线上的设备状态查询和远程操作确认。
3. **数字孪生** — 3D 可视化场景中的自然交互控制。

| 方向 | 类型 | 说明 |
|------|------|------|
| P4 → 服务端 | gesture | 手势事件 |

| 服务端 → P4 | ack | 确认消息 |

## 九、ai_agent + Skill

### 9.1 AI Agent 架构

AI Agent 是 VelaGesture 的核心决策组件，采用事件驱动架构：

```
事件源                     事件队列              策略引擎
  手势事件  -----+          +----------+         +---------+
  告警推送  -----+--------> | FIFO     | ------> | 规则匹配 |
  语音意图  -----+          | 32 slots |         | 动作分发 |
  用户命令  -----+          +----------+         +----+----+
                                                      |
                                                      v
                                               +-----------+
                                               | Skill     |
                                               | Executor  |
                                               +-----------+
```

### 9.2 guxian-control Skill

自定义 Skill，提供两个能力：

**query_status** — 查询古贤系统状态

参数：
- target: "system" | "device" | "scene" | 设备ID

**execute_action** — 执行古贤系统操作

参数：
- action: "confirm_alert" | "locate_device" | "switch_scene"
- alert_id / device_id / scene_id: 可选的关联标识

Skill 文件安装路径：
```
/data/agent/skills/guxian-control/SKILL.md
```

## 十一、主动 + 执行场景

完整闭环：

```
1. 古贤系统检测到异常（如：7号闸门水位超限）
   |
2. WebSocket 推送告警到 P4 设备
   |
3. AI Agent 接收告警，存储为待确认状态
   |
4. 设备显示 "收到告警：水位超限 — 请做OK手势确认"
   |
5. 用户做 OK 手势
   |
6. 稳定门控确认手势稳定
   |
7. Agent 调用 guxian-control Skill 执行确认操作
   |
8. 古贤系统确认告警已被处理
   |
9. 设备显示 "告警已确认 — 7号闸门"
```

这个场景展示了完整的"感知 → 决策 → 执行 → 反馈"闭环。

## 十二、音频链路

```
麦克风
  |
  v
I2S 驱动 → PCM (16kHz/16bit/单声道)
  |
  v
WebSocket 二进制帧 → 服务端 ASR
  |
  v
语音意图 → AI Agent
  |
  v
Agent 决策 → Skill 执行
  |
  v
结果 → TTS → PCM → WebSocket → 扬声器
```

- 半双工模式
- 不做 AEC（回声消除）
- 不做 barge-in（打断）
- 服务端 ASR（设备不做本地语音识别）

## 十三、技术创新与工程实现

### 13.1 创新点

1. **嵌入式手势交互** — 在资源受限的 ESP32-P4 上实现实时手势识别和 AI Agent 决策。
2. **稳定门控算法** — 简洁有效的连续帧过滤机制，平衡响应速度和准确性。
3. **Skill 扩展架构** — 文件化的 Skill 定义，支持运行时发现和调用。
4. **多模态融合** — 手势 + 语音 + WebSocket 三种交互渠道统一到 Agent 决策引擎。

### 13.2 工程决策

1. **不做本地大模型** — P4 资源不足以运行 LLM，推理在服务端完成。
2. **半双工音频** — 避免 AEC 的复杂性，可靠性优先。
3. **直接帧分类** — 不做 21 关键点中间表示，降低计算量。
4. **规则引擎优先** — Agent 决策使用规则而非 LLM，保证实时性。
