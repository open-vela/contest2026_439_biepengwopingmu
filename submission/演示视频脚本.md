# VelaGesture — 演示视频脚本

**时长：** ≤ 5 分钟

---

## 场景 1：系统启动 (0:00 – 0:30)

**画面：** ESP32-P4 开发板 + 串口终端

**操作：**
1. 给开发板上电
2. 串口终端显示 openvela 启动日志
3. 输入 `velagesture` 启动应用
4. 显示各子系统初始化完成

**旁白：**
"这是 ESP32-P4 Function-EV-Board 运行 openvela 系统。
VelaGesture 应用启动后，依次初始化技能执行器、WebSocket
客户端、AI Agent 和手势感知模块。"

---

## 场景 2：手势识别 (0:30 – 1:30)

**画面：** 摄像头画面 + 串口终端

**操作：**
1. 将手放在摄像头前
2. 做 OK 手势 → 串口显示 "Stable gesture: ok"
3. 做握拳手势 → 串口显示 "Stable gesture: fist"
4. 做张开手掌 → 串口显示 "Stable gesture: open_palm"

**旁白：**
"摄像头实时识别手势。稳定门控机制要求同一个手势持续
5 帧才触发事件，避免误触。当前支持 OK、握拳、张开
手掌等手势。"

---

## 场景 3：WebSocket 通信 (1:30 – 2:00)

**画面：** 双屏 — 串口终端 + 古贤业务系统界面

**操作：**
1. 张开手掌触发状态查询
2. 串口显示 WebSocket 发送消息
3. 古贤界面显示查询被接收

**旁白：**
"手势事件通过 WebSocket 发送到古贤业务系统。古贤系统
是面向水利监控的数字孪生平台，运行在服务器端。"

---

## 场景 4：AI Agent + Skill (2:00 – 2:30)

**画面：** 串口终端

**操作：**
1. 显示 Agent 处理手势事件
2. 显示 guxian-control Skill 被调用
3. 显示查询结果返回

**旁白：**
"AI Agent 根据手势类型决定执行什么动作。张开手掌触发
状态查询，使用 guxian-control Skill 与古贤系统交互。"

---

## 场景 5：主动告警 + 执行 (2:30 – 4:00)

**画面：** 双屏 — 串口终端 + 古贤界面

**操作：**
1. 古贤系统检测到异常，推送告警
2. 串口显示收到告警消息
3. 屏幕显示 "收到告警：7号闸门水位超限 — 请做OK手势确认"
4. 先做握拳 → 告警被取消
5. 再次触发告警
6. 做 OK 手势 → Agent 确认告警
7. Skill 执行确认操作
8. 古贤界面显示告警已被确认
9. 设备显示 "告警已确认"

**旁白：**
"这是完整的主动加执行场景：古贤系统检测到水位超限，
通过 WebSocket 推送告警到设备。设备的 AI Agent 提醒
用户，用户做 OK 手势确认。Agent 调用 guxian-control
Skill 执行确认操作，古贤系统返回结果，设备显示任务
完成。"

---

## 场景 6：语音交互 (4:00 – 4:30)

**画面：** 串口终端

**操作：**
1. 对麦克风说 "查看状态"
2. 串口显示音频帧被捕获
3. 显示语音意图被识别
4. 显示状态查询结果

**旁白：**
"除了手势，系统还支持语音交互。语音通过 WebSocket 发
送到服务端进行识别，识别结果转化为结构化意图，由 Agent
执行相应操作。"

---

## 场景 7：总结 (4:30 – 5:00)

**画面：** 串口终端

**操作：**
1. 按 Ctrl+C 停止应用
2. 显示各子系统依次关闭
3. 显示 "VelaGesture terminated cleanly."

**旁白：**
"VelaGesture 运行在 ESP32-P4 上的 openvela 系统。它将
手势识别、AI Agent 决策、WebSocket 通信和古贤业务系统
整合为一体。本项目不是从零开发，而是在已有多模态手势
终端原型基础上，迁移到 openvela 嵌入式平台的系统升级。"

---

## 注意事项

- 所有时间点为参考，可根据实际演示节奏调整
- 如果摄像头推理尚未接入真实模型，跳过场景 2 中的手势
  识别展示，改用串口手动注入事件
- 不要伪造不存在的功能
- 不要编造性能数据（FPS、延迟、准确率）
